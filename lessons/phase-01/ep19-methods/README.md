# EP.19 — เพิ่ม method ให้กับชนิดข้อมูล

Phase 1 — Go Basic • [สารบัญ](../../../docs/playlist-01-go-basic/README.md)

## เป้าหมายและสิ่งที่ควรรู้ก่อน

เรียกการตรวจสถานะจาก Reading ก่อนเริ่มควรเรียน EP.18 และอธิบายตัวอย่างในตอนนั้นด้วยคำของตนเองได้ สามารถเปิดตัวอย่างประกอบระหว่างฝึกได้

เรียนตามลำดับ: ทำความเข้าใจ → คาดเดาผล → รันโปรแกรม → ลองแก้ทีละจุด หากต้องการทบทวน เปิด [ตอนก่อนหน้า](../ep18-structs/README.md)

## แนวคิดและคำใหม่

เมื่อมีแบบฟอร์มการวัดแล้ว เราตั้งวิธีอ่านสถานะไว้คู่กับชนิดข้อมูลนั้น ผู้เรียกจึงเขียน reading.IsWarning() ได้

method คือฟังก์ชันที่มี receiver; receiver อยู่ในวงเล็บก่อนชื่อ method ระบุชนิดที่ผูกด้วย; value receiver รับสำเนาค่าในตัวอย่างนี้

## ลองคาดเดาผลลัพธ์ก่อนรัน

r ใน method มาจากตัวแปรใดตอนเรียก reading.IsWarning()?

จดผลที่คาดเดาและเหตุผลสั้น ๆ ก่อนรัน แล้วเปรียบเทียบกับผลจริง หากต่างกัน ให้ลองอธิบายว่าเกิดจากส่วนใดของโค้ด

## โค้ดตัวอย่าง

### examples/main.go

```go
package main

import "fmt"

type Reading struct {
	Celsius float64
}

func (r Reading) IsWarning() bool {
	return r.Celsius >= 30
}

func main() {
	reading := Reading{Celsius: 30}
	fmt.Println(reading.IsWarning())
}
```

## อธิบายการทำงานของโค้ด

- (r Reading) คือ receiver ไม่ใช่ parameter หลังชื่อ method
- IsWarning อ่านค่าและคืน bool ไม่แก้ต้นฉบับ
- จะเขียนเป็นฟังก์ชัน isWarning(reading Reading) ก็ได้ การเลือก method เป็นการออกแบบให้พฤติกรรมอยู่กับชนิด

**หลักภาษาและแนวทางออกแบบ:** รูปแบบคำสั่งและชนิดข้อมูลเป็นหลักของภาษา Go การแยกโค้ดตามหน้าที่เป็นแนวทางออกแบบให้เข้าใจง่าย ส่วนชื่อโฟลเดอร์และการใช้หนึ่ง module ต่อ EP เป็นทางเลือกในการจัดหลักสูตร

## ข้อผิดพลาดที่พบบ่อย

- ใส่ receiver ไว้หลังชื่อ method: ตำแหน่งนั้นจะกลายเป็น parameter
- หวังให้การแก้ r.Celsius ใน value receiver เปลี่ยนต้นฉบับ: บทนี้ r เป็นสำเนา
