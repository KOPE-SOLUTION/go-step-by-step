# EP.20 — ใช้ pointer เมื่อต้องการแก้ค่าต้นฉบับ

Phase 1 — Go Basic • [สารบัญ](../../../docs/playlist-01-go-basic/README.md)

## เป้าหมายและสิ่งที่ควรรู้ก่อน

อธิบาย & และ * พร้อมติดตามค่าที่ถูกแก้ได้ ก่อนเริ่มควรทำ EP.19 ได้และอธิบายตัวอย่างด้วยคำของตนเอง ไม่จำเป็นต้องจำโค้ดจากความจำ

บทนี้มีหนึ่งเรื่องหลัก อ่านเป็นช่วงได้: ทำความเข้าใจ → คาดเดา → รัน → เปลี่ยนทีละจุด ถ้าต้องกลับไปทบทวนใช้ [ตอนก่อนหน้า](../ep19-methods/README.md)

## แนวคิดและคำใหม่

การส่งสำเนาแบบฟอร์มไม่เปลี่ยนใบเดิม แต่ pointer เหมือนบอกตำแหน่งของใบเดิม ผู้รับจึงแก้ข้อมูลที่ตำแหน่งนั้นได้

pointer คือค่าที่ชี้ไปยังตัวแปร; &value ให้ pointer ไปยัง value; *float64 คือชนิด pointer ไปยัง float64; *p ในคำสั่งคือค่าที่ pointer ชี้; pointer ที่ยังไม่กำหนดเป็น nil และนำมา dereference ไม่ได้

## หยุดคาดเดาก่อนเปิดผล

ถ้าฟังก์ชันรับ float64 ธรรมดาแล้วแก้ภายใน ค่า temperature ภายนอกจะเปลี่ยนไหม?

จดคำตอบสั้น ๆ ก่อนรัน ผิดได้ เก็บเหตุผลที่คิดไว้เทียบกับสิ่งที่เกิดขึ้น

## ตัวอย่างเล็กที่รันได้

### examples/main.go

```go
package main

import "fmt"

func addOffset(value *float64, offset float64) {
	*value = *value + offset
}

func main() {
	temperature := 25.0
	addOffset(&temperature, 0.5)
	fmt.Println(temperature)
}
```

## ทำไมโค้ดจึงทำงานแบบนี้

- &temperature ส่งตำแหน่งตัวแปรให้ฟังก์ชัน
- *value ทางซ้ายของ = เขียนค่าที่ตำแหน่งนั้น ทางขวาอ่านค่าเดิม
- ตัวอย่างต้องส่ง pointer ที่ไม่เป็น nil; ไม่ต้องใช้ pointer กับทุกอย่าง ใช้เมื่องานต้องแก้ต้นฉบับหรือมีเหตุผลชัดเจน

**แยกประเภท:** syntax และชนิดข้อมูลเป็นหลักของภาษา; การแยกหน้าที่ให้ส่วนเล็กอ่านง่ายเป็นแนวทางออกแบบ; ชื่อโฟลเดอร์และการใช้หนึ่ง module ต่อ EP เป็นทางเลือกของหลักสูตร เกณฑ์อุณหภูมิที่พบเป็นข้อกำหนดจำลอง

## ข้อผิดพลาดที่พบบ่อย

- ส่ง temperature แทน &temperature: float64 ไม่ตรงกับ *float64
- ใช้ var p *float64 แล้วเขียน *p: p เป็น nil ต้องมีตัวแปรให้ชี้ก่อน
